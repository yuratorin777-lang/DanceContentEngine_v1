# Dance Content Engine — Channel Strategy v1

**Status:** Draft for implementation
**Pilot geography:** Серпухов

## 1. Principle

Channels are not interchangeable distribution pipes. Each channel has a specific job in the audience decision journey.

The system should create one underlying content asset and adapt it to the channel instead of independently inventing unrelated content for every platform.

## 2. Core channel set

### VK — primary public social channel

**Role:** discovery, local visibility, discussion, trust and conversion support.

Best suited to:
- author posts;
- educational posts;
- problem-solving posts;
- local content;
- photos/videos;
- progress and performance proof;
- commercial announcements.

Primary decision stages:
- awareness;
- exploration;
- comparison;
- first contact.

VK is the primary social laboratory for testing different content angles and measuring audience response.

### Telegram — relationship and depth channel

**Role:** deepen trust and maintain an ongoing relationship with parents.

Best suited to:
- owner's voice;
- deeper explanations;
- behind-the-scenes thinking;
- practical parent guidance;
- observations and reflections;
- follow-ups around ongoing activities.

Primary decision stages:
- exploration;
- adaptation;
- progress;
- loyalty.

Telegram should not simply duplicate VK word-for-word.

### Website / SEO — evergreen decision-support layer

**Role:** capture durable information demand and provide deep reference content.

Best suited to:
- age guides;
- style guides;
- comparison articles;
- FAQs;
- first-lesson guides;
- adaptation guides;
- local decision-support pages;
- structured proof / methodology pages.

Primary decision stages:
- exploration;
- shortlist;
- comparison;
- first contact.

This channel should prioritize genuinely useful pages, not mass programmatic SEO.

### Dzen — secondary long-form test channel

**Role:** test whether longer educational and authorial content finds incremental reach outside the core social channel.

Best suited to:
- long-form parent decision support;
- authorial essays;
- deep educational material;
- evergreen explanations.

Dzen should initially be treated as a controlled experiment, not as a core production obligation.

## 3. Video distribution

Video is a format layer that can feed several channels.

The future video automation system should create reusable assets such as:

- short clips;
- subtitles;
- voiceover variants;
- captions;
- descriptions;
- platform-specific metadata.

The source video should not force the same edit on every platform.

## 4. Channel adaptation model

The architecture should follow:

**One content idea → one core evidence package → multiple channel adaptations.**

Example:

Core idea: “Ребёнок говорит «не хочу».”

VK:
- concise, discussion-friendly post.

Telegram:
- deeper owner explanation and practical guidance.

Website:
- evergreen decision-support article.

Dzen:
- long-form narrative/explainer if the topic proves valuable.

Short video:
- one concrete insight or myth-breaking point.

## 5. Channel priority

Initial priority:

**Tier 1**
- VK;
- Website / SEO;
- Telegram.

**Tier 2 / experiment**
- Dzen.

**Format expansion**
- short video and long video distribution through the publishing system as the video automation becomes available.

Additional channels should not be added until a clear role and measurement method exist.

## 6. What should not be done yet

Do not:

- launch every possible platform;
- copy the exact same text everywhere;
- build separate content calendars that ignore the shared content asset;
- create a channel because a competitor has one;
- optimize for vanity follower counts without a decision-stage purpose.

## 7. Channel-specific content emphasis

| Channel | Core role | Strongest content types |
|---|---|---|
| VK | discovery + trust + local conversion | authorial, educational, problem-solving, proof, local, commercial |
| Telegram | depth + relationship | authorial, educational, parent guidance, behind-the-scenes |
| Website / SEO | evergreen decision support | guides, comparisons, FAQs, age/style content, methodology |
| Dzen | incremental long-form reach | deep explainers, essays, decision support |
| Video layer | attention + demonstration | short insights, demonstrations, owner voice, progress, events |

## 8. Channel planning principle

Content Planning should eventually create separate channel plans from one common strategic content system.

Each plan should contain:

- content asset;
- target audience segment;
- decision stage;
- content job;
- channel;
- format;
- publishing date/window;
- CTA when appropriate;
- source/evidence;
- linked assets;
- analytics fields.

## 9. Channel performance logic

Success is not measured identically across channels.

VK should emphasize:
- reach;
- engagement;
- profile actions;
- messages;
- clicks;
- leads.

Telegram should emphasize:
- views/read depth where available;
- reactions;
- replies;
- link actions;
- returning audience signals.

Website/SEO should emphasize:
- impressions;
- clicks;
- engaged sessions;
- search query coverage;
- assisted conversions;
- leads.

Dzen should emphasize:
- reach;
- read depth;
- engagement;
- transitions;
- incremental audience contribution.

Video should emphasize:
- starts;
- completion/retention;
- saves/shares;
- profile actions;
- assisted conversions.

Exact metrics will be finalized when the Analytics Collector is designed.

## 10. Strategic boundary

Channel Strategy does not decide the exact publication frequency forever. Frequency should be determined by available production capacity, audience response and analytics evidence.

The goal is a sustainable operating system, not maximum posting volume.

## 11. Future evolution

Once analytics accumulates sufficient evidence, the system should be able to answer:

- which channel works best for which decision stage;
- which content jobs work best on each channel;
- which content assets deserve cross-channel expansion;
- where Dzen creates incremental value;
- which channels should receive more or less production capacity.

Until then, the channel structure above is the v1 operating model.
