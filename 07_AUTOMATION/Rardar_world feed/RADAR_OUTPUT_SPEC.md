# 1. PURPOSE

`RADAR_OUTPUT_SPEC.md` описывает, что представляет собой результат работы Radar / World Feed и как другой AI должен его читать и использовать.

Radar не является контент-генератором.

Radar не принимает контентные решения.

Radar не составляет контент-план.

Radar не определяет, какую публикацию необходимо создать.

Его задача:

> собирать внешнюю информацию, структурировать её, удалять дубликаты, классифицировать и передавать дальше в систему.

Основной принцип:

```text
EXTERNAL INFORMATION
        ↓
RADAR
        ↓
COLLECTION
        ↓
DEDUPLICATION
        ↓
CLASSIFICATION
        ↓
RELEVANCE
        ↓
STRUCTURED OUTPUT
        ↓
DOWNSTREAM AI

История запусков:

runtime/latest.json

Исторические файлы используются только тогда, когда необходимо сравнить результаты разных запусков или восстановить прошлые данные.

5. RADAR IS NOT THE CONTENT DECISION MAKER

Это критически важное правило.

Radar отвечает:

"Что произошло / что обнаружено / какая информация найдена?"

Следующий AI отвечает:

"Имеет ли это отношение к нашей контентной задаче?"

Контентная система отвечает:

"Нужно ли использовать это в контенте и каким образом?"

Поэтому Radar не должен:

писать посты;
придумывать заголовки;
составлять публикации;
определять контент-план;
самостоятельно решать, что публиковать;
превращать каждый найденный материал в контентную идею.
6. OUTPUT STRUCTURE

Основной объект результата:

{
  "engine": "...",
  "version": "...",
  "runAt": "...",
  "realWorldData": true,
  "focus": {},
  "statistics": {},
  "sourceBreakdown": [],
  "signals": []
}
7. ENGINE

Поле:

engine

указывает систему, которая сформировала результат.

Пример:

DanceContentEngine Radar / World Feed
8. VERSION

Поле:

version

указывает версию Radar, сформировавшую результат.

AI не должен предполагать, что разные версии Radar имеют полностью одинаковую структуру.

При изменении версии необходимо ориентироваться на фактическую структуру текущего latest.json.

9. RUN TIME

Поле:

runAt

указывает дату и время формирования результата.

Это важно для определения актуальности информации.

10. REAL WORLD DATA

Поле:

realWorldData

указывает, что результат сформирован на основе внешних источников.

Если:

"realWorldData": true

данные следует рассматривать как результат реального сбора внешней информации.

Однако это не означает, что каждый отдельный факт автоматически является полностью проверенным утверждением.

11. FOCUS

Поле:

focus

описывает текущий фокус Radar.

Например:

"focus": {
  "local": [
    "Серпухов",
    "Московская область",
    "Россия"
  ],
  "globalFeed": true
}

Это означает:

локальная зона — Серпухов;
Radar работает также с российским информационным пространством;
глобальный World Feed включён.
12. STATISTICS

Раздел:

statistics

содержит техническую статистику запуска.

Например:

sourcesConfigured
sourcesSucceeded
sourcesFailed
rawFacts
uniqueFacts
duplicatesRemoved
classifiedFacts
relevantSignals
durationMs

Эти показатели описывают работу двигателя.

Они не являются содержанием для публикации.

13. SOURCE BREAKDOWN

Раздел:

sourceBreakdown

показывает состояние каждого источника.

Он используется для диагностики:

какие источники успешно обработаны;
какие источники не ответили;
сколько материалов получено;
сколько времени занял сбор;
какие ошибки произошли.

AI не должен считать отсутствие материала из одного источника доказательством отсутствия события в реальном мире.

14. SIGNALS

Главный информационный массив находится в:

signals

Каждый элемент представляет отдельный информационный материал, прошедший обработку Radar.

Типовая структура:

{
  "id": "...",
  "source": "...",
  "sourceScope": "...",
  "sourceWeight": 1,
  "title": "...",
  "url": "...",
  "content": "...",
  "publishedAt": "...",
  "collectedAt": "...",
  "analysis": {}
}
15. ARTICLE IDENTITY

Поле:

id

используется для идентификации материала.

Оно не является содержательным выводом.

ID используется технически для:

дедупликации;
хранения;
сравнения;
обработки данных.

AI не должен интерпретировать ID как смысловой показатель.

16. SOURCE

Поле:

source

указывает источник/канал, через который материал был обнаружен.

Пример:

Google News — dance children development

Это не обязательно означает, что Google News является первоначальным автором материала.

Для оценки самого материала необходимо использовать:

title;
url;
source;
content;
publishedAt.
17. SOURCE SCOPE

Поле:

sourceScope

описывает информационную область источника.

В текущей системе используются:

LOCAL
RUSSIA
GLOBAL
18. SOURCE WEIGHT

Поле:

sourceWeight

используется Radar при расчёте релевантности.

Это технический коэффициент.

Он не является оценкой истинности материала.

Например:

0.7

не означает:

"материал на 70% достоверен".

Это означает только, что источник имеет соответствующий вес в алгоритме Radar.

19. TITLE

Поле:

title

содержит заголовок обнаруженного материала.

AI может использовать его для первичного понимания темы.

Заголовок не следует считать полным доказательством содержания материала.

20. URL

Поле:

url

содержит ссылку на обнаруженный материал или ссылку, предоставленную внешним feed.

URL используется для:

перехода к первоисточнику;
проверки;
дополнительного чтения;
верификации;
дальнейшей аналитической работы.

Если для принятия важного решения необходимо подтвердить содержание, AI должен обращаться к источнику, а не ограничиваться заголовком.

21. CONTENT

Поле:

content

содержит доступный текстовый фрагмент материала.

Он используется как дополнительный информационный контекст.

Если content отсутствует или содержит мало информации, AI не должен самостоятельно заполнять отсутствующие сведения.

22. PUBLISHED AT

Поле:

publishedAt

указывает время публикации материала, если оно доступно и корректно распознано.

Дата важна для оценки актуальности.

23. COLLECTED AT

Поле:

collectedAt

указывает время, когда Radar получил материал.

Это не обязательно дата публикации.

Разница:

publishedAt = когда материал появился
collectedAt = когда Radar его обнаружил
24. ANALYSIS

Раздел:

analysis

содержит машинную классификацию материала.

Он не является человеческим экспертным заключением.

25. RELEVANCE

Поле:

relevance

представляет числовую оценку соответствия материала алгоритму Radar.

Диапазон:

0–100

Важно:

relevance не означает истинность факта.

Высокая relevance означает:

материал хорошо соответствует информационным критериям Radar.

Она не означает:

материал доказан на 100%.

26. RELEVANCE LEVEL

Поле:

relevanceLevel

может содержать:

HIGH
MEDIUM
LOW
BELOW_THRESHOLD

Это классификация по релевантности.

27. CONTENT POTENTIAL

Поле:

contentPotential

указывает потенциальную пригодность материала для дальнейшего контентного анализа.

Это не команда создать контент.

Например:

contentPotential = 80

означает:

материал потенциально интересен следующему уровню системы.

Это не означает:

"нужно написать пост".

28. PRIMARY CATEGORY

Поле:

primaryCategory

определяет основную классификацию материала.

В текущей версии могут использоваться:

LOCAL_DANCE
DANCE_WORLD
CORE_DANCE
ADJACENT_DOMAIN
LOCAL_ECOSYSTEM

Фактический набор категорий необходимо определять по текущему latest.json и текущей версии Radar.

29. MATCHED CATEGORIES

Поле:

matchedCategories

показывает, какие тематические категории были обнаружены в материале.

Это результат алгоритмического сопоставления ключевых признаков.

Он не является окончательной смысловой интерпретацией материала.

30. CONFIDENCE

Поле:

confidence

указывает техническую уверенность Radar в наличии достаточного идентификатора материала.

Это не медицинская, научная или экспертная вероятность истинности утверждения.

AI не должен интерпретировать это значение как:

"вероятность того, что новость правдива"
31. FACT VS INTERPRETATION

Критически важно разделять:

обнаруженный материал

и

вывод AI

Radar преимущественно поставляет:

SOURCE DATA

и

MACHINE CLASSIFICATION

Он не создаёт окончательные экспертные выводы.

Поэтому следующий AI должен различать:

SOURCE FACT

То, что непосредственно содержится в обнаруженном источнике.

RADAR CLASSIFICATION

То, что вычислено алгоритмом Radar.

AI INTERPRETATION

То, что следующий AI выводит самостоятельно.

Эти три уровня нельзя смешивать.

32. HOW DOWNSTREAM AI SHOULD READ RADAR

Следующий AI должен работать следующим образом:

1. Открыть latest.json
        ↓
2. Прочитать statistics
        ↓
3. Проверить sourceBreakdown
        ↓
4. Прочитать signals
        ↓
5. Для каждого сигнала изучить:
   - title
   - url
   - content
   - publishedAt
   - sourceScope
   - primaryCategory
   - relevance
   - matchedCategories
        ↓
6. При необходимости перейти к источнику
        ↓
7. Отделить факт источника от своей интерпретации
        ↓
8. Только после этого использовать материал
33. WHAT DOWNSTREAM AI MUST NOT DO

Следующий AI не должен:

считать каждую запись готовой контентной идеей;
считать relevance доказательством истинности;
считать confidence вероятностью истинности;
придумывать отсутствующие сведения;
выдавать классификацию Radar за экспертный вывод;
игнорировать дату материала;
автоматически публиковать обнаруженную информацию;
считать один источник достаточным доказательством для критически важных утверждений.
34. RADAR AND THE KNOWLEDGE SYSTEM

Упрощённая схема:

EXTERNAL WORLD
      ↓
RADAR / WORLD FEED
      ↓
runtime/latest.json
      ↓

      ↓
KNOWLEDGE / ANALYSIS / CONTENT SYSTEM

Radar поставляет материал для дальнейшей обработки.

36. IMPORTANT SYSTEM RULE

Radar должен оставаться информационным двигателем.

Не следует превращать его в:

контентщика
копирайтера
стратега
редактора
маркетолога
эксперта по здоровью

Его задача значительно проще:

найти → собрать → структурировать → классифицировать → передать.

Следующий уровень системы самостоятельно определяет, что делать с этой информацией.
